# Android acceptance tests

Use a device/emulator with a current Android System WebView provider. Install the debug APK. Install Housecall Pro (`housecall.pros`) for tests 2–9 and 11–13; sign in if its launcher requires that. Use Android Settings → Apps → Special app access → Display over other apps → 1st Rate HQ to manage overlay access. Record OS/API, device, navigation mode, WebView version, and actual outcome. None of these tests is claimed as executed until a device run is recorded.

1. **Fresh install:** Uninstall HQ, reinstall, and open it. Expect the labeled Native Integration Test page without a permission prompt. Type a persistent value, force-stop and reopen HQ; expect it restored. The in-memory field need not survive process death.
2. **First installed-HCP launch:** Clear HQ app data, open HQ, tap Open Housecall Pro. Expect the HQ explanation with both choices. Choose Allow floating HQ button, enable the switch in Android Settings, and press Back. On API 33+ respond to notification permission. Expect HCP to launch and a 56dp HQ bubble to appear within about one second, on the right with its center about 30% above the usable bottom. Inspect navigation/cutout clearance.
3. **Permission declined:** Revoke overlay access. If testing first explanation, clear HQ data. Tap Open Housecall Pro and choose Not now, or choose Allow but return from Settings without granting. Expect HCP to launch, no bubble, no crash, no Settings loop. Return and open HCP again: expect no repeated explanation. Explicit Request Overlay Permission must still show the explanation.
4. **Return tap and state:** Enter different values in both test fields and record Document loads. Open HCP and tap the bubble quickly. Expect the same field values, unchanged load count, no overlay over HQ, and one HQ task in Recents. Repeat with the notification's body. Use `adb shell dumpsys activity activities` to inspect MainActivity instances if needed.
5. **Reopen:** After test 4, switch to HCP via Recents without calling HQ.openHcp: expect no bubble. Return to HQ and use Open Housecall Pro: expect the bubble again. The existing hidden-service session deadline is retained.
6. **Drag:** Hold the bubble roughly 300ms; expect a close target. Move slowly and rapidly: expect tracking within safe bounds, full opacity, then snap to nearest edge on release. Small pre-hold movement below touch slop must permit a tap; pre-hold movement above slop must cancel tap/drag. Release a long stationary hold away from close: expect docking, no HQ return. Simulate a cancelled gesture (rotation or interrupt touch): expect target removed, no false tap or close.
7. **Persistence and configuration:** Dock left at a distinct height, close the service, then reopen HCP from HQ. Expect saved side/Y. Repeat on the right, rotate, change navigation mode, and use split screen if supported. Expect the entire bubble inside safe bounds and sensible normalized Y. Rotate HQ with text in the in-memory field: expect the same document. Force-stop HQ and reopen: expect localStorage/history restoration, with in-memory state allowed to reset.
8. **Drag close:** Hold and drag toward the bottom center target (64dp, bottom edge roughly 48dp above safe navigation area). Expect activation within about 60dp of centers, one brief haptic on entry, none continuously inside. Exit and reenter: one new haptic allowed. Release inside: expect bubble, target, inset probe, service, and notification removed. Verify with `adb shell dumpsys activity services com.firstrate.hq` and `adb shell dumpsys window windows`.
9. **Notification:** Grant notification access, launch HCP, inspect ongoing title/text and Close bubble action. Body tap must return to existing HQ state and hide overlay while notification/service remains. Close bubble must remove all service resources. On API 33+ deny notification permission on fresh data: HCP/bubble must still work; normal notification drawer display may be absent and Android's active-apps/Task Manager indicates the service. Never expect a notification action that the OS has hidden.
10. **Missing HCP and store:** Uninstall HCP and tap Open Housecall Pro. Expect market listing, no bubble. Disable/remove market handler on a test emulator and repeat: expect HTTPS listing. With no market or browser handler, expect a helpful message and no crash.
11. **Repeated calls and rapid switching:** In remote WebView debugging (debug builds only), run `for(let i=0;i<20;i++) HQ.openHcp()` while HQ is foreground. Expect one permission/launch operation, no duplicate bubble/target/notification/activity. Repeatedly return/open, tap notification rapidly, invoke stop twice, and use Request Permission while an explanation is open. Expect no duplicates, leaks, or crashes. Repeat with an already hidden service.
12. **Revocation:** Start bubble, revoke overlay permission in Android Settings, wait approximately one second while awake, then return to HQ and open HCP. Expect service cleanup and normal HCP launch without bubble. Restore permission and explicitly reopen: expect recovery. Revoke camera access and test scanner: expect denial handling and no blindly granted resources.
13. **Expiry:** Build `.\gradlew.bat assembleDebug -PhqDebugTimeoutMs=60000` and install that APK. Open HCP, note elapsed start, return to HQ, and reopen at 30 seconds. Expect full cleanup around the original 60-second deadline (not 60 seconds after re-show). Restore normal build by omitting the property. Also test sleeping across the deadline: Android may defer alarm execution during sleep; on waking the watchdog must stop the overdue session. Release builds always cap at eight hours. Kill the process while active: expect no automatic restart; explicitly opening HCP is required for another bubble. Persisted elapsed time/boot count must never create an overdue session.
14. **Version matrix:** Repeat permission, launch/return, drag/close and notification tests on API 26/27 (Android 8/8.1), 30/31 (package visibility/background rules), 33 (notification permission), 34/35 (specialUse foreground service), 36 and installed 37.2 (target restrictions/edge-to-edge). Include gesture and three-button navigation, cutouts, rotation, and any fleet OEM with battery management. Compilation does not establish these runtime outcomes.
15. **Camera:** Tap Test Camera, approve CAMERA, expect video. Stop Camera must release tracks. Deny permission on fresh install and retry: expect status error, no crash. Open HCP and return during a camera request; verify no stale grants. No audio permission may be requested or granted.
16. **Bridge security:** On a debug build, inspect the WebView with Chrome. External HTTPS link navigation must open a browser, never replace HQ. Load an external iframe: it must have no native bridge. Attempt a trusted-origin iframe call: transport must reject non-main-frame messages. Malformed/unknown bridge messages must do nothing. Confirm file/content URLs and mixed HTTP resources are blocked. The bridge wrapper may be absent on obsolete providers; update System WebView and verify native calls resume.
